## Delivery boundary

GitHub Pages continues to serve static assets. `server/contact` is a separate Node 24 service using either the official Mailgun sending endpoint or Brevo transactional endpoint. Keys stay on the owner's server. The frontend receives only `PUBLIC_CONTACT_ENDPOINT`, provided through the repository Actions variable during build. Localhost endpoints are allowed for local development, but rejected in GitHub Actions builds.

The service fixes sender and recipient from server configuration, places visitor email in Reply-To, sends plain text, checks allowed browser origins and input/body limits, supports a honeypot, and applies bounded per-IP/global in-memory rate limits. These measures do not constitute distributed bot authentication; CORS is not treated as authentication. Provider acceptance is distinguished from inbox delivery. Messages, provider bodies and credentials are excluded from logs. No autoresponder is sent.

Mailgun reference: https://documentation.mailgun.com/docs/mailgun/user-manual/api-key-mgmt/rbac-mgmt and https://documentation.mailgun.com/docs/mailgun/api-reference/send/mailgun/messages/post-v3--domain-name--messages . Brevo reference: https://developers.brevo.com/docs/send-a-transactional-email . Static hosting reference: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages . FormSubmit was considered, then excluded following the owner's preference to use their existing services.

Setup is in `server/contact/README.md`, with environment examples, direct Node launch, an unverified Docker build/run example, reverse proxy/TLS, DNS, and the GitHub Actions variable. Public DNS lookup of the selected name returned ENOTFOUND from this environment. No DNS record, remote server, inbox, provider credential, or GitHub setting was changed. The running local service has no credentials and correctly reports unavailable; browser success/error examples are intercepted only in the isolated QA browser. The owner's ordinary preview never uses a fake success service.

## Conversational form and authored send motion

The owner asked for friendlier narration, question-style labels, a gently changing invitation, and button text that liquefies into a paper plane before flying away. ID and EN now use natural conversational labels (for example, “Boleh tahu namamu?” / “What should I call you?”), an invitation starting “Hai, mari bicara tentang…” / “Hi, let’s talk about…”, and “Kirim ke saya” / “Send to me”. Error, unavailable and no-script messages were softened without hiding the delivery state.

The rotating visual topic has a 3.6s readable hold and a 300ms swap. All topic sizes are reserved in the same grid cell, avoiding field movement. The accessible message label keeps the visible invitation prefix and a stable generic “pesanmu” / “your message” ending; animated alternatives are aria-hidden. Rotation stops while the form has focus, while sending, off screen, outside the professional world, in a hidden document, or under reduced motion. Without JavaScript the first invitation remains readable.

`ContactSend.astro` is a custom inline SVG, not a template component. A bounded 200×60 SVG displacement/blur deforms a replica of the actual label, coalescing it into an organic ink path (480ms). Native compatible cubic-path interpolation turns that mass into the plane silhouette (420ms), then its shaded fold becomes visible. Only affirmative API acceptance releases a 680ms curved flight. An error restores the label and retains the draft; it never starts flight. The request starts immediately in parallel with preparation, not after a decorative delay. Status is communicated in text as soon as the API outcome is known. Keyboard submission and reduced motion use the quiet status-based path.

Transform and opacity use native animation controls, while SVG attributes use native `<animate>` for the requested non-composite shape change. This intentionally incurs bounded SVG painting rather than applying a large filter to the page. Reference: https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/animate . No new library, dependency or hydrated island was added. The label replica inherits the actual button font so mobile text does not jump in size.

A revision counter owns the sequence. Resize, reduced-motion changes, page hiding, world crossing and chapter navigation cancel effects and resolve pending visual stages. Controls and attribute animations are removed on completion or cancellation. New text typed while an older message is sending is not erased by its successful completion.

The isolated browser checks cover full melt/fold/wait/flight phases, genuinely animated displacement, early request dispatch, a held plane before acceptance, no flight on failure, restored labels, attribute cleanup, stable topic geometry and accessible names, focus pause, quiet keyboard behavior, EN/ID at 320/390/768/1440px, resize/navigation/reduced-motion interruptions, and preservation of an in-flight edit. All checks passed. The full unit suite still has 33 passing tests, and build/typecheck plus 151 static-output checks pass.
